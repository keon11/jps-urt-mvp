# Phase 4 engineering architecture and reuse inventory

The working Medplum / HAPI-CQF / Keycloak / PostgreSQL / Grafana / llama.cpp-Qwen components remain. No redundant rules engine, workflow system, crawler or orchestration platform was introduced. Existing CQF recommendations, policy approvals, payer simulator and six demonstration cases are preserved.

## Data and FHIR

Synthea 4.0.0 is the Apache-2.0 generator, pinned to the exact upstream binary SHA-256. Java 21 ran the fixed-seed population and clinical-history exporter. Original generated bytes remain private. A documented derived FHIR R4 clinical cohort is committed with source hashes, fictional labels and tagged resources; optional provider context/contact identifiers are projected out. Generated Locations resolve conditional references in actual local writes. The projection is not a complete chart, original export or evidence of current admission suitability.

Existing @medplum/fhirtypes 5.2.6 (Apache-2.0), @medplum/core 5.2.6 (Apache-2.0), Zod 4.1.12 (MIT), Node fetch and SHA-256 support the narrow adapter. It provides GET-only endpoint-pinned pagination, read scopes/token-provider renewal, bounded HTTP retries, denial/error handling, response identity checks and source reconciliation. It never changes Epic/JPS data. SMART discovery endpoint/PKCE checks use public metadata; real token exchange is delegated to an authorized token provider and is not performed without a registered sandbox client. No OAuth server or clinical rules engine was rewritten.

Actual local Medplum writes/reads and pagination are distinguished from HAPI base-resource validation and mocked transport failures. HAPI unknown-extension warnings remain visible; profile claims are removed only from validation copies. Full FHIR/US Core IG validation and authenticated Epic acceptance remain production work.

The read-only /api/synthetic-cohort projection exposes the generated histories to the Operations workspace with source hashes and clinical evidence. It does not insert them into the original six-case queue, generate current-admission recommendations or silently score historical records. Pure clinical tests confirm missing current criteria remain insufficient evidence.

## Policy and risk

Existing Cheerio 1.1.2 (MIT), robots-parser 2.3.0 (MIT) and jsdiff 8.0.4 (BSD-3-Clause) remain the evidence tools. Official CMS retrieval obeys robots checking and records source bytes/date uncertainty; no private contracts or official executable criteria are inferred.

Owned synthetic payer cases exercise exact-plan/wildcard precedence, explicit priority, ties/conflicts, dates, exceptions, approval and pending-state isolation. The live risk-evidence action reads the current published illustrative registry through the existing authorization-review context. No new rule is activated by a golden test, no private plan assumption is made, and missing evidence is not a confirmed violation. Flags are ordinal; no calibrated adjudication probability is claimed.

## Reliability and desktop

The existing queue benchmark is extended to a 3600-second profile with the same 10,006-row workload, 25 sessions, token renewal and thresholds; a sampled RSS gate is added in advance. Request rows stream to disk, status/RSS sample every 15 seconds, and aggregate results are recomputed independently. The hour load is separate from case-mutating tests and dependency faults. Independent source/build/document work and extended synthetic Medplum/HAPI validation during the run is disclosed as shared-host activity. The benchmark is not a Synthea clinical-inference capacity test.

OpenTelemetry, prom-client, actual local dependency alerts, durable intent/conditional FHIR receipts and full restore/audit checks are reused. New artifact destinations keep earlier proof immutable. No single-host result establishes HA, a production SLA, multi-day stability or HIPAA compliance.

The unnamed clinical workstation uses existing React 19.1.1 (MIT), lucide-react 0.468.0 (ISC) and Playwright 1.56.1 (Apache-2.0) checks. Added evidence panels use existing hospital panel/table styles. Fixture preview remains static, read-only and disconnected; no backend/credential is deployed. Remote project permission/protection is a separate external gate.

## Reproduction and license limits

Run `python3 scripts/generate-synthea.py`, then `npx tsx scripts/verify-synthea.ts` after local infrastructure is ready. The verifier retrieves public SMART discovery itself; unavailable public discovery is reported separately from local tests. The committed derived corpus supports local unit/browser work without downloading a jar. Java/Node/runtime and direct-library license evidence is retained; the generator binary is not redistributed in Git. Complete transitive/container/model legal review remains production work. See licenses/Synthea-4.0.0-LICENSE.txt and the existing dependency/container/model inventories.

The jar's embedded license/notice entry hashes are inventoried in artifacts/issue-4/synthea-license-inventory.json. Upstream Apache-2.0 is not a blanket grant for every terminology, transitive component or payer criterion. SNOMED/LOINC/other code-system redistribution and commercial rights need explicit legal review before production/commercial distribution; no license-gated criteria terms were accepted by this demo. This is a runtime/license evidence inventory, not legal clearance.
