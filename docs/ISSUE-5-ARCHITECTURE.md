# Issue #5 performance design and limits

Existing Medplum, HAPI/CQF, Keycloak, PostgreSQL, Grafana, local llama.cpp/Qwen, workflow adapters and React workstation are preserved. No new NPM dependency, container, cache engine, orchestrator or cloud resource was installed. Installed reuse/license metadata is in artifacts/issue-5/reuse-inventory.json; this is not a full transitive/container legal clearance.

The only product-path change specializes the existing paginated queue SQL for an exactly empty search. It removes an always-true ILIKE predicate and reuses the existing covering sort index. Nonempty searches still use bound, escaped parameters. The selected columns, source-derived encounter class/payer, stale-priority handling, stable ordering, current count and pagination remain the same. The schema parser still enforces query bounds. There is no stale result/count cache, token verification cache or authorization bypass. Write-side policy/authorization/clinical/audit code is unchanged.

An explicit operator-only ordinary VACUUM/ANALYZE probe is restricted to the loopback isolated synthetic database. It repairs visibility/statistics after fixture restore/rewrite and never changes clinical/workflow values. It is not a new production maintenance policy or a command to run against hospital data. Compare original/optimized plans on both unmaintained and maintained state and retain the separate diagnostic probes; do not attribute combined gains only to application SQL. Production maintenance scheduling and representative write-heavy tests remain necessary.

The original API is copied from the Phase 4 commit into a private immutable source directory. Installed dependencies and fixed synthetic queue are shared; source hashes are verified. Both full runs use the same Phase 5 harness and 25 sessions, page/offset sequence, request deadline, token renewal, trace sampling and duration. No case-mutating suites or outage drills overlap the hours. Product SQL changes and initial builds preceded the accepted baseline; documentation/report tooling and Git/CI work continued on the shared host. Unavoidable scheduling is disclosed. Full ordered case-row hashes verify identical queue contents before/after maintenance and optimized load. A 30-second V8 CPU/event-loop window appears in both runs. The inspector is loopback-only, restricted to a read-only benchmark process, and closes after capture. A repaired profiler was validated in a separate short run before the full comparison.

Raw request rows contain only session ordinal, elapsed time, status and latency. They stream during measurement, are independently recomputed, then gzip-compressed with SHA-256 round-trip verification for transfer. No tokens, clinical content, credentials or private dumps are published. Child exit terminates a run early and prevents a short duration from passing. Stage markers preserve completed hours if a later regression fails; no threshold or missed zero-timeout target is hidden.

The static fixture preview remains explicitly disconnected and read-only, with a separate loopback backend for the eight interactive demonstrations. Vercel configuration allows only the requested development branch and disables main/prior branches. Actual remote project permission/protection remains an external gate. No production, insurer/Epic connectivity, HIPAA compliance, HA/SLA or clinical accuracy claim follows from these local synthetic measurements.
