# Security, compliance and production readiness assessment

**Classification: synthetic demonstration only. Not approved for clinical use, coverage determinations, PHI or production deployment. No HIPAA/HITECH compliance certification is claimed.**

## Implemented and verified controls

- Only the six exact, fictional fixture bundles are accepted at intake. All resources carry synthetic classification tags. Clinical update fields are numeric and human/payer reasons are predefined choices; the demo does not ingest real clinical notes or call JPS/Epic systems.
- API and published service ports bind to loopback. Clinical and payer actions remain internal. The only model calls target the local CPU service; no paid model provider, telemetry containing patient content or external model training is configured.
- Keycloak JWT verification checks signature, expiry, issuer, audience and application role. Server-side route restrictions separate reviewer and advisor actions. No Medplum service secret is sent to the browser.
- Session cookies are HttpOnly and SameSite=Strict. Origin checking, a restrictive content policy, frame protection, body-size limits and basic sign-in throttling are present. API responses are not cached.
- Audit events include actors, timestamps, inputs/outputs, evidence versions and model/rule lineage. Appends are serialized and hash-chained; a database trigger rejects audit updates/deletes. The complete chain can be verified independently by script.
- Missing/stale/invalid clinical evidence prevents an affirmative clinical recommendation. Invalid/unavailable AI becomes a clearly labeled rules-only fallback; CQF failure does not create a successful assessment. Human decisions require current assessment and active escalation; overrides need an explicit reason.
- The Grafana database role can select only an aggregate view. Live tests confirm denial of direct access to case/audit tables. Dependencies are pinned, the model is checksum-verified, and npm audit results are retained.

## Desktop preview assessment (Issue #1)

The static preview contains only explicitly marked fictional snapshot data. Credential values are removed from the frontend, sign-in is not used in preview mode, mutations are read-only, external links to local services are hidden, and build artifacts are scanned for known local passwords, local-only credential patterns, tokens, private keys and source maps. Browser verification checks for zero API/external requests. Static headers restrict connections to the same origin, disable framing and indexing, and prevent content sniffing. These measures do not replace Vercel deployment protection, which cannot yet be verified because project creation returned 403.

Historical commits and isolated backend fixture configuration contain intentionally public local-only defaults. This change preserves that history and does not rotate or publish any external credential. Those defaults are not secure credentials for a network-accessible backend; all must be replaced before any real deployment. No claim of HIPAA compliance, validated medical necessity, payer certification, clinical model performance or complete accessibility compliance is made. A live preview integration additionally needs verified HTTPS, secure sessions, origin/CSRF controls, scoped identity, synthetic-only isolation, monitoring and access review. Production gaps listed above remain open.

## Issue #2 governance limits

The policy lifecycle and internal authorization review are functional synthetic workflows. Original policy bytes are immutable at the application level; the database administrator remains able to alter/drop schema and triggers, so this is not a certified WORM evidence store. Existing Keycloak demo roles provide server-verified identity, but role aliases do not establish real clinical credentials or organizational delegated authority. Source retrieval may be restricted; unknown dates/applicability remain unresolved and cannot become approved executable official criteria. No private payer contract, MCG/InterQual content, HIPAA certification, insurer connectivity or independent clinical validation is claimed. The fixture preview has no publication capability; original local-only defaults remain unsuitable for a public service.

Reliability evidence is bounded: one local host, 120 seconds of paginated reads, 25 synthetic sessions, isolated database restore and controlled FHIR/model outages. p99 exceeded one second even when the p95 gate passed. This does not establish long-duration operation, failover, disaster recovery across sites, clinical throughput or population-level accuracy. The legacy full-bundle endpoint and UI are not certified for the paginated API's 10,000-row benchmark. Remaining requirements include cross-session recovery of pending simulator intents, qualified clinical/payer validation, delegated real roles, SSO/MFA, secure production secrets, encrypted storage, retention, incident response, full SBOM/container scans, external trace/alert operations, approved Epic client registration and JPS authorization. Vercel project creation is still denied with 403; hosted protection/linkage cannot be verified without an authorized project connection.
